## 当前状态

2026-09-21：scripts 之外在主代码完成 harness 启动可达性 precheck。
落地：
1. harness-config.yml 新增 eyes_mcp 段(command/health_check_on_startup/startup_timeout_seconds)，HarnessConfigLoader.fromMap 解析到 HarnessEyesMcpConfig，默认值 command='eyes-mcp' / startup_timeout_seconds=5。
2. HarnessStateWriter.discover(llmConfig, eyesMcp) 启动时按 ProcessBuilder 拉起 stdio，先用临时 eyes-mcp-probe.jsonl 写入 initialize + notifications/initialized + tools/list（单行 JSON），主线程后台读 stdout 解析 serverInfo.name/version 与 tools.size，并行读取 stderr 用于失败诊断；超时后 destroyForcibly 并返回 unhealthy；清理临时文件；healthy/unhealthy/disabled 三态。
3. HarnessState.EyesMcpStatus record（available / status / serverName / serverVersion / toolCount / durationMs / error / checkedAt）写入 harness-state.json；空参保持向后兼容（HarnessState 7 参构造器自动填 disabled）。
4. NioHttpServer.healthPayload(llmConfig, systemState) 新增 eyes_mcp 字段（status / available / server_name / server_version / tool_count / duration_ms / error / checked_at）。
5. 前端：src/main/resources/web/console/openeyes-mcp-health-plan.js + 2 场景测试；/console/ 的 Runtime Health 块新增 OpenEyes MCP 健康卡（healthy/done / disabled/paused / unhealthy/failed 三态）；loadHealth() 缓存 state.health，renderRuntimeHealth() 读取 state.health.eyes_mcp。
