## Borrowing decision

1. **`s1kit` -> per-question confidence cutoff (adopted as evidence; no semantics change).** The `parallel_questions` / `confidence-routing` pair in our plan currently carries two global lines (`lowStakesThreshold 0.60`, `highStakesThreshold 0.85`, plus `keepThreshold = 0.5` inherited from `fast-jev-compaction`). s1kit's own sample shows the usable cutoff for the *same* model differing by more than 2x across question types (0.3333 vs 0.7143) while both reach 100% precision at very different coverage (100% vs 40%). A single global threshold therefore either over-blocks cheap questions or under-blocks expensive ones. Recorded under the §11 checklist item 4 evidence note; thresholds, checklist and semantics are unchanged and still need maintainer sign-off. Evidence grade: lead, not proof — 0 stars, three days old, README numbers not reproduced (no key, no sample of ours).
2. **`dsh-jev-goal-judge` -> question text and state must be separate (adopted as evidence).** Our §11 item 9 already requires the question strings to live in one file and to be edited as constants. dsh adds the stronger half: the *asked* text is constant while the observed transcript travels only in the `state` data field, so tool output can never rewrite the question. Our judgment layer builds question sets out of runtime facts and tool results, so this is the injection surface to check. Recorded as an evidence note under §11 item 9; no code and no checklist change this round. Evidence grade: lead — 1 star, but it ships a real-key smoke with numbers.
3. **`Flide` -> fan-out must be answer-equivalent to single-question (adopted as evidence plus one candidate acceptance item).** Our `parallel_questions` adaptation layer (graph plan path B) currently records only the win — 13 questions in one call, 12.2x cheaper, 10x faster — and not its precondition. Flide's README states the precondition explicitly: generic batched inference recomputes state and injects delimiters, and those delimiters change the answers. If our adaptation layer batches without that guarantee, one call covering a whole decision tree imports answer drift into every branch. Recorded under graph plan §2.4 as evidence; the proposed acceptance item (sample fan-out answers against isolated single-question answers) is a candidate for maintainer sign-off, not a committed checklist change. Evidence grade: lead — 7 stars, but a 121 MB self-hosted inference stack is far from our own runtime.
4. **Not adopted this round.** `Jev bias audit` (134,772 counterfactual answers; an identity label moves predictions 3-15 points while an associated name moves them by fractions of a point) and `Jev calibration audit` are calibration-sample design material for M4 — worth reading, but they change the replay sample design, which is a separate piece of work. `Jev, job by job` compares TypeSafe's own job-by-job against what the model actually did, which is evidence that cookbook claims need local re-verification — that is already our standing rule for the FEAT-03 real-key path, so nothing new to record.
